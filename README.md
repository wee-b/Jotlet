# Jotlet

一个纯客户端的事件记录应用，基于 Electron、TypeScript 和 Vite。无需账号，没有后端或云同步，数据保存在本机。

默认窗口为当前最小尺寸 860 × 580，可继续放大。小窗口下压缩侧栏和顶部留白，设置页及编辑弹窗保留底部操作区；月视图根据格子高度显示日程，其余通过「还有 N 个日程」查看。

## Windows 安装与卸载

`npm run make` 生成 `out/make/nsis/x64/Jotlet-版本-Setup.exe`。向导首页提供「安装 Jotlet」「卸载 Jotlet」；没有已安装版本时，卸载选项不可选。兼容检测旧版 Squirrel 的卸载入口。

安装流程依次选择程序安装目录、数据保存目录。两个目录需要相互独立；首次启动时使用选择的数据目录，已有数据会保留原副本并安全迁移。若目标与现有位置都有数据，则拒绝自动覆盖。之后在应用设置中改过的位置，会在后续启动和安装向导中继续使用。

安装仅作用于当前 Windows 用户，无需管理员权限。请在安装或卸载前关闭 Jotlet。卸载保留数据文件夹和用户设置，只清理程序所分发的文件、快捷方式和卸载注册项。迁移程序安装位置时，会先移除旧程序文件。

首次构建下载并校验固定 SHA-256 的 NSIS 3.12 编译器，缓存于 `.cache/nsis-3.12`。`npm run test:installer` 在临时目录和独立注册表键中验证安装、卸载、中文路径、目录限制及数据保留。

## 日历与日程

- 首页默认展示日历周视图，可切换到月视图。左侧迷你月历可选择日期，顶部支持前后翻页、回到今天和跳转到指定日期。
- 点击月历空白处、周历时间格或「创建日程」打开编辑窗口；支持主题、起止时间、全天、描述，以及浅绿／浅杏／浅蓝／浅粉／浅紫五种浅色。原有“所属日历”分类已移除，旧数据读取时自动转换为颜色。
- 绑定事件为可选项，默认「不绑定事件（独立日程）」，无需创建事件即可保存日程。选择已有事件后，可从日程打开对应的事件时间线；删除日程不影响事件，删除事件也不会删除日程。
- 在绑定下拉框选择「新建事件并绑定」，输入名称后点击「创建并绑定」即可创建事件，并自动添加一条初始记录：内容使用当前日程主题（未填时使用事件名称）和描述，发生时间使用日程开始时间。事件与记录一起保存；保存当前日程后完成关联。即使取消当前日程，已明确创建的事件和记录仍会保留。
- 日历顶部日期、事件筛选、今天、翻页、周／月切换和创建日程排成一行。「只显示事件／全部显示」可切换是否仅显示已绑定现有事件的日程，筛选同时作用于月／周视图、迷你月历和当天日程列表。
- 日历侧栏保留当天日程列表，不再提供日程搜索入口；周视图支持跨天显示和重叠日程并排展示。
- 周视图仅显示整点分隔线，鼠标悬停时只高亮所在的半小时。单击空白处创建半小时日程，按住向下拖动可按半小时递增选择更长时段；拖动到边缘自动滚动，按 Esc 可取消选择。
- `Ctrl / Cmd + N` 创建日程；切换到「事件」后使用原有事件快捷键，通过内容区的「添加记录」为当前事件添加记录。
- Windows 标题栏与顶部导航合并，空白区域可拖动窗口；右上角自定义按钮支持最小化、最大化／还原和关闭，悬停底色为内缩圆角。窗口本身仍由系统处理圆角和缩放，关闭时保留未保存内容的保存流程。自定义最大化按钮不提供系统悬停分屏菜单。应用级导航仅保留一处 Jotlet 标识。
- 日程独立存于数据文件夹下的 `calendar.json`，写入前保留 `calendar.json.bak`。读取失败时禁止覆盖原文件。`.jotlet` 完整备份包含日程；兼容 JSON / Markdown 导出仅包含事件和记录。

## 设置

- 日历与事件页面左下角均有「设置」入口，可调整默认视图、默认日程时长、默认颜色及周视图起始时段。
- 「保存设置」「返回日历」统一位于设置页底部。点击「保存设置」后保存到本机，下次启动继续使用。新设置用于后续创建的日程；周视图单击仍固定选择半小时，拖动选择时长。
- 「恢复默认」会填回默认选项，点击「保存设置」后生效。设置页也可打开「数据与备份」说明。
- 导入、导出和数据说明入口统一放在「设置 → 数据与备份」。默认完整备份使用 `.jotlet` 扩展名，包含事件、记录、日程、颜色和关联关系。
- 「文件保存位置」显示当前数据文件夹。更改文件夹会复制事件、日程和自动备份，验证成功后立即切换；原文件夹保留副本。目标已有 Jotlet 数据时拒绝覆盖，迁移失败仍使用原位置。
- 导入先选择 `.jotlet` 文件，再选择没有 Jotlet 数据的保存文件夹；导入成功后使用备份中的数据，并将该文件夹设为应用后续保存位置。取消任一步或校验失败时，不改变当前数据和保存位置。
- 保存位置记录在原 `userData/data-location.json` 中，下次启动自动使用；自定义目录不可访问时提示错误，不会静默创建空数据库。

## 事件与时间线

- 以事件组织事情：事件包含名称、开始时间、可选的结束时间，以及多个进展节点。
- 左侧按所有事件、进行中、已结束和置顶筛选；事件列表展示起止时间、最新进展和节点数量。
- 点击事件，右侧以卡片时间线展示事情的发展。从左向右按发生时间排列，宽度不足时自动换行；支持追加、编辑和删除节点。
- 追加节点时可以填写过去的发生时间。早于事件开始的补录会自动提前开始时间；已结束事件的节点不能晚于结束时间，可以先调整时间或重新开启事件。
- 点击起止时间修改事件时间，点击「标记结束」设置结束时间，也可以重新开启事件。
- 搜索同时匹配事件名称和全部节点内容。事件名称停止输入约 450 ms 后自动保存；节点在点击「保存记录」后保存。删除事件会一并删除全部节点，删除均需确认，暂无回收站。
- `Ctrl / Cmd + N` 新建事件，`Ctrl / Cmd + K` 搜索，`Ctrl / Cmd + S` 立即保存事件名称。

## 导入、导出与迁移

- `.jotlet` v1 是带格式标记和版本号的 UTF-8 JSON 完整备份，保存事件、全部记录与日程，保留原始 ID、关联关系、颜色及时间信息。校验失败或版本不受支持时不写入目标目录。
- JSON v2 事件备份包含事件名称、起止时间、置顶状态及记录，不包含日程；Markdown 用于阅读。它们作为兼容导出选项保留。
- 本机存储兼容旧版 JSON v1。每条旧记录转换为一个事件，原内容成为初始节点，保留原 ID、置顶状态和创建、更新时间。此兼容仅用于读取已有数据，不提供 JSON 文件导入入口。
- 本机在所选数据文件夹使用 `notes.json` 与 `calendar.json`。首次写入新版事件格式前，将旧文件原样保留为 `notes.json.v1.bak`，该迁移副本不会随日常保存轮换。
- 导入仅支持单个 `.jotlet` 完整备份，大小不超过 20 MB。文件选择器与主进程均限制格式，JSON / MD / TXT / .jetlet 等其他后缀不支持导入。格式或内容校验失败时不改变当前数据和保存位置。
- Markdown 导出按事件组织，并按时间顺序展示每个节点，适合阅读；完整恢复请使用 `.jotlet` 备份。

在「设置 → 数据与备份」中查看或更改本地保存位置，默认是 Electron `userData` 目录。事件写入前保留上一版 `notes.json.bak`。读取失败时停止编辑，不覆盖原文件；先复制备份，再修复文件并重启。数据文件与 `.jotlet` 备份未加密，请使用系统账户保护隐私。

## 开发

应用图标沿用绿色叶片标识，矢量源文件为 `assets/jotlet.svg`。修改后运行 `npm run icons` 生成 PNG、多尺寸 ICO 与 ICNS；窗口、可执行文件、安装包和网页图标均使用这套资源。

```sh
npm ci
npm start
npm run lint
npm run typecheck
npm test
npm run package
```

测试需要 Node.js 22.6+，使用内置测试运行器。`npm run package` 生成当前平台应用，`npm run make` 生成安装包。

主进程负责受限的本地文件操作，渲染进程通过隔离的 preload 接口访问事件。生产应用阻止网络请求和外部页面导航，内容以纯文本展示。
